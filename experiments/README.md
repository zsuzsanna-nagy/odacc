# ODACC Experiments

This directory contains the experiment runners used for the evaluation of
ODACC, the exact online data-aware object-centric conformance-checking method
described in the accompanying paper.

The runners execute `batch_folder.py` on the benchmark suites, store the raw
outputs of each run, and generate aggregate CSV/JSON files for subsequent
analysis.

## Experiment runners

### `run_validation.py`

Runs the non-Order-Management benchmark suites used for semantic validation and
the smaller scalability experiments.

For these benchmarks, both the proposed symbolic method and the SMT-based
formulation are executed in combined online/offline mode (`mode="both"`).
The resulting runs are used primarily for semantic validation by comparing 
online prefix-alignment results with the corresponding exact offline computation.

The configured suites include:

- comprehensive benchmarks;
- object-attribute benchmarks;
- component scaling;
- deviation scaling;
- extended deviation scaling;
- prefix-length scaling;
- component-merge scaling;
- extended merge scaling;
- simple, medium, and complex guard configurations.

### `run_online_symbolic.py`

Runs the proposed symbolic online method over the full benchmark collection.

This includes the non-Order-Management benchmarks as well as the
Order-Management-derived suites:

- component executions;
- fitting executions;
- controlled control-flow deviations;
- controlled data deviations;
- controlled object-relation deviations;
- two-deviation cases;
- three-deviation cases;
- stress cases with four or five injected deviations.

The runner uses the `symbolic_smt` backend configuration and `mode="online"`.

Per-observation output generated by these runs also contains the information
used for the certification-route analysis.

### `run_online_smt.py`

Runs the exact SMT-based reference formulation over the same online benchmark
collection as `run_online_symbolic.py`.

The runner uses the `smt_smt` backend configuration and `mode="online"`.

The symbolic and SMT runs are kept in separate runners because the SMT
experiments are substantially more computationally demanding and can therefore
be executed or resumed independently.

## Experimental protocol

The paper experiments use the following configuration:

- measured repetitions: **1**
- warm-up repetitions: **0**
- online run timeout: **600 s**
- offline run timeout: **600 s**
- per-observation timeout: **60 s**
- native solver retries: **1**

Each benchmark configuration was executed once for the completion analysis.
Cases with execution times close to the specified timeout were repeated when
needed to verify the completion classification.

The runtime values reported in the paper correspond to these measured runs;
the experiment should therefore be executed on an otherwise lightly loaded
machine when reproducing timing results.

## Configuration

Before running the experiments, set the path to the CoCoMoT installation in
each runner:

```python
COCOMOT_ROOT = Path("../cocomot-main")
```

## Running the experiments

```bash
python run_validation.py
python run_online_symbolic.py
python run_online_smt.py
```
